# Специфікація вимог та use cases

## Намір
Сформувати функціональні вимоги EARS, сценарії прийняття Gherkin, користувацькі історії, діаграму use case-ів та матрицю трасування зв'язків існуючуї ER-діаграми

## Актори
* User - зареєстрований користувач, веде список перегляду і залишає відгуки
* Guest - незареєстрований користувач, може лише переглядати список тайтлів
* External API - зовнішня система, постачає дані про тайтли (`title`, `synposis`, `release_date`) та жанри.

## Головні цілі та use cases
* UC-1: Перегляд каталогу аніме за жанрами (`Anime`, `Genre`).
* UC-2: Оновлення статусу перегляду аніме в особистому списку (`UserAnimeStatus`: дивлюсь, в планах, переглянуто).
* UC-3: Написання та публікація відгуку з оцінкою (`Review`: `score`, `text`).
* UC-4: Синхронізація бази аніме із зовнішнім API (`Anime`, `Genre`).

## Критерії прийняття
* Описати вимоги у форматі EARS (WHEN/WHILE/IF ... SHALL). Вимоги мають бути однозначними, тестованими та явно посилатись на сутності й атрибути ER моделі.
* Написати user stories та Gherkin-сценарії (Given/When/Then).
* Побудувати матрицю трасування у форматі таблиці Markdown (вимога ↔ сценарій/UC).
* Створити use case діаграму, яка повинна містити узагальнення акторів (user успадковує права guest), підсценарії (`<<include>>`) та умовні розширення (`<<extend>>`).
